## Campaign preconditions and limits (proposed TasteGate policy)

Before ANY live request, a reviewer must explicitly approve the probe list and maximum dispatches; the operator privately confirms attributable event access, numeric quota, burst/concurrency limit, expiration, support contact and permitted capture/display/export/retention. Organizer documentation gives no numeric entitlement. Confirm the owner's actual film and tag interpretations; synthetic fixture selections cannot substitute for them.

Use only `https://hackathon.api.qloo.com`, GET, `X-Api-Key` header, `Accept: application/json`, standard URL query encoding, no redirects, no automatic retries or fallback. Never put a credential in a URL, CLI flag, prompt, screenshot, tracked file or log. Never send names of people as users, emails, device/account IDs or location histories. Public artist/movie/venue names are cultural entity queries, not customer identity. Use no demographics/sensitive-trait inputs. [Official safety policy](https://github.com/qloo/qloo-hackathon-kit/blob/0db91b8d9c5aae2160d53596e57ea6c9da251cde/docs/SAFE_USE.md).

Each dispatch, including failure and pagination, counts. One in flight, <=4 seconds including response reading, <=64 KiB accepted body in the initial profile, no hidden pages. P01-P09 have a proposed combined ceiling of **17 raw HTTP dispatches**. P10 is a separate audit capped at **14** total dispatches, <=60 seconds, <=1 repair round. Thus the REST campaign is <=31; one independent CLI raw search adds <=1, for <=32. These are consumer ceilings, not Qloo quotas. Do not run all probes merely to spend the allowance. The `find_tags` normalized workflow's underlying dispatch count is not yet verified and is **excluded/blocked** until independently bounded and separately allocated. One CLI command is not assumed to equal one HTTP call.

For EVERY dispatch save private request method/path and allowlisted parameters without auth headers; UTC/local call ID and run ID; source revision and uncommitted-source manifest; exact status and safe response headers; capped raw body in a restricted private directory; SHA-256, duration, raw field paths actually observed, warnings and missingness; expected vs observed outcome and dispatch counter. Never fabricate an upstream request ID; record one only if actually present. See the [ledger](PHASE1B_PROBE_LEDGER_TEMPLATE.md). No live data may enter public fixtures or the review ZIP from this offline phase.

**Universal stop conditions:** 401 stops the campaign; 403 stops the affected capability; 429 stops the campaign without retry; 400/404 stops that request profile for investigation; 5xx/network/deadline/malformed/oversized body stops that probe with UNKNOWN. Quota uncertainty, rights/privacy concern, unexpected redirect, unapproved host/parameter, unconfirmed identity or exhausted cap stops before dispatch. A 2xx response alone never passes a probe. Do not manufacture auth/rate-limit/server faults. Use offline injection for failure cases. After dispatch, do not blindly repeat a timed-out request; any later fresh read requires a new reviewed ledger allocation.
